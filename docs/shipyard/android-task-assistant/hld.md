## 目的与成功标准

在小米 15 真机（Android 16 起）上运行独立 App，处理支付宝蚂蚁森林能量与任务、
起点读书福利中心任务，以及名单 APP 的每日签到。可单独启停、手动运行并查看每项结果；
具体任务以真机实际页面可识别且可验证为准。

设计阶段列过的蚂蚁庄园饲料、芭芭农场领取暂未实施，仍保留在规划内，后续排期实现。

## 前提、约束和假设

- 开发环境（Android SDK + adb）与真机连接已就绪；每一步适配以真机取证为验收依据，未验证的不标记为支持。
- 页面可能更新、控件不可访问或要求人工验证，不能保证全部任务自动完成。定时执行受系统后台限制影响。

## 使用方式与边界

用户安装 App、手动启用无障碍服务、登录目标 App，选择任务后启动或设置执行时间。涉及支付、下单、订阅、授权、分享邀请、验证码及其他不可确定的操作时暂停并提示，不替用户确认。截图中的旧衣回收下单属于此类。用户于 2026-11-08 明确要求浏览广告任务，纳入支持范围；仅按页面正常流程观看并验证结果，不绕过广告或验证；失败时记录并退出。抽奖仅在明确免费且无需额外授权时尝试，支付或条件不明时暂停。

## 设计决策

<a id="hld-1"></a>

### [x] 1. 运行方式
- 结论：原生独立安卓 App，通过无障碍服务执行界面操作，不依赖 root 或电脑常驻。
- 依据：用户明确选择独立 App；无障碍服务是可行的普通应用操作路径。

<a id="hld-2"></a>

### [x] 2. 任务模块
- 结论：森林、庄园、农场和起点分别配置和运行；先覆盖可识别的领取、签到及普通浏览任务，具体动作以实机结果为准。
- 依据：用户要求单独处理四类任务；缺少其他页面和完整流程。

<a id="hld-3"></a>

### [x] 3. 安全边界
- 结论：敏感动作暂停，用户本人处理；不读取或保存密码、支付信息，不绕过验证码或风控。
- 依据：任务包含下单等潜在额外后果，按最小必要操作设计。

<a id="hld-4"></a>

### [x] 4. 调度和记录
- 结论：支持手动和尽力定时执行、停止、结果记录；锁屏、系统省电或权限不足时明确提示，不能保证准时运行。
- 依据：移动系统限制以及用户自动化目标。

<a id="hld-5"></a>

### [x] 5. 识别策略
- 结论：优先无障碍节点和页面状态校验；不可访问的画面可评估截图识别，但须经过真机验证和独立授权；不凭截图固定坐标宣称可靠。
- 依据：给定截图无法证明目标控件暴露在无障碍树中。

## 模块与数据概览

App 界面管理任务开关、启动/停止、调度和日志；无障碍执行器根据当前应用和页面状态运行各任务模块，向本地记录结果。设置与日志只保存在本机；无需服务器。目标应用没有可依赖的公开接口，具体入口和页面契约待实机核验。

## 用户补充的任务路径（2026-11-08）

- 起点：我 → 福利中心 → 激励任务、完成 3 个广告任务得奖励、去携程签到领积分。
- 蚂蚁森林：找能量，包含可重复收取、一键收、上滑继续；领奖励中的浏览广告任务；能量雨、赚能量、去抽奖。
- 此补充扩展原先默认关闭广告的假设；需要实机逐项验证，免费抽奖以页面规则为准。庄园和芭芭农场仍在规划内，待后续实现。

## 每日签到与一键自动化（2026-11-11）

用户新增需求：对名单 APP 自动每日签到，放在起点任务之前；整体设计灵活，后续可新增 APP。
用户拍板：各任务保留单独运行入口，最前面新增「自动化」按钮一键串跑全部任务
（每日签到 → 起点任务 → 森林任务 → 森林能量）；单个 APP 签到失败跳过继续，不阻塞后续。
（该顺序已于 2026-11-20 调整，见文末「自动化顺序调整」，当前以那里为准。）

<a id="hld-6"></a>

### [x] 6. 名单驱动的签到框架
- 结论：签到规格（包名/首页入口/弹窗优先/底部标签/标签页入口）声明在 `CheckinApps` 注册表，
  新增 APP 只加一条规格；`DailyCheckinRunner` 用同一套「等前台 → 找入口 → 点签到 → 认完成标记」状态机执行。
- 首批名单：RQrun（首页「签到福利」）、E充站（弹窗「立即签到」优先，否则右上角「签到」，
  签到页点日历「今天」格）、比亚迪（「我的」→ 右上角「签到」）。包名已于 2026-11-11 真机 pm list + aapt 标签核对：
  cn.runningquotient.rq / cn.charge / com.byd.aeri.caranywhere。用户口述「E充电」经确认实为依威能源 E充站（cn.charge）；
  国网真·E充电 com.sgcc.evs.echarge 本机未安装，不纳入。
- 依据：用户要求灵活扩展；三个 APP 的路径差异只在入口段，签到段可复用。

<a id="hld-7"></a>

### [x] 7. 任务串联
- 结论：`RunCoordinator.startChain` 维护待执行队列，当前任务自行收尾后按序接续，前台服务保持到链尾；
  用户停止、运行异常、手动切换任务都会清空队列。起点/森林任务运行器补充「不在前台就自启动」，
  森林任务冷启动复用既有恢复路径（支付宝首页 → 蚂蚁森林 → 领奖）。
- 依据：协调器原本一次只跑一个任务且由主界面负责启动目标 APP；串联后每个运行器须自足。

<a id="hld-8"></a>

### [x] 8. 签到安全边界
- 结论：新增 `CHECKIN` 闸门场景，只允许精确文案「签到/立即签到/去签到/签到福利」，
  外加日历型签到页的唯一动作「今天」；同屏推广（签到领红包等）与交易类文案一律拒绝。
  完成标记（已签到/签到成功/明日再来/明天再来）只读不点。
- 依据：与携程签到同一授权边界——只完成用户点名的签到动作，不替用户参加推广。

## 自动化顺序调整（2026-11-20）

用户要求森林能量排在森林任务之前：一键自动化调整为
每日签到 → 起点任务 → 森林能量 → 森林任务。森林能量只依赖支付宝主页的「找能量」入口；
森林任务常停在森林内页/奖励弹窗，先跑能量可以少一次回主页恢复。
